# GZSL 论文研究

**当前目标：创造全新的原生三分支协同框架。** 当前仍在问题与机制探索，第三分支、通信机制、主攻 Idea、代码父起点和正式 RUN 尚未确定；工程原型不等于已成立的方法。

三支应地位对等、各有不可替代的类别证据、最终 logits 前通信，并在同次前向与反向中协同优化。下一步是确定可证伪的机制，而不是自动继承旧框架或继续编号。

## 日常只看这三个入口

| 我要知道 | 入口 |
|---|---|
| 为什么做、当前在验证什么 | [Idea 与研究问题](research/IDEA_TREE.md) |
| 怎么开工、代码放哪、结果怎么记 | [实验操作规范](docs/EXPERIMENT_PROTOCOL.md) |
| 框架叫什么、原实验和代码在哪里 | [框架与证据总账](research/LEDGER_INDEX.md) |

```text
Idea：问题与假设
  → Experiment：确认父代码、比较条件、初始化来源
    → RUN：准确代码、配置、真实结果
      → 决定：继续 / 修订 / 停止
        → owner 接纳：按框架名冻结同一份实现
```

## 最少维护

- 新框架用具体名称，正式快照用 `<method_id>/<commit前8位>`；不再续编 V8、V9。旧 V 标签、目录和编号保留为历史兼容入口。
- 每个 Idea 一张卡；每个新 Experiment 一份 `EXPERIMENT.yaml` 和一份 `RUNS.csv`。配置保留一份并引用，需要框架图时按规则提供。
- 同一次实际执行只有一个 RUN 身份；快速筛选到完整验证沿用同一记录体系，不复制 TRY 成绩。
- 代码目录稳定，正式接纳不强制搬代码。代码父起点、比较基线、初始化权重是三件事。
- 当前管理事实以 GitHub `main` 为准；旧实验分支的 README 是历史快照。离线时使用最近核实的 main，并披露同步状态。
- 未接纳代码不混入 main；公开上传与本地保存分开记录。论文交付快照仍只在 owner 明确要求时生成。

本次整理不指定新框架的正式名称或代码父起点，不启动实验，不删除历史。服务器实时运行状态尚未核实。
