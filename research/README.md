# Idea：一张卡持续积累

Idea 属于项目总库，跨研究主线和框架复用。卡片保存于 `ideas/IDEA-xxx_<slug>.md`；新编号先查 [跨分支索引](RECORD_INDEX.csv)，旧编号不改、不复用。

## 每张卡只维护五项内容

1. **问题与假设**：为什么研究、什么现象能否定它。
2. **机制与来源**：改变什么，直接论文/实验来源是什么。
3. **判断条件**：运行前写成立、停止条件与适用范围。
4. **实验引用**：原 Experiment/RUN 的准确位置，不另抄完整数字。
5. **结论与演化**：当前支持/否定什么、失败边界、按日期追加的决定。

工作状态、证据结论与是否接纳必须分清，允许用简短文字表达，不强迫旧卡批量补三套状态字段。例如“研究暂停；特定条件下有信号；未接纳”。旧 status 和原结论保留，后续解释追加。

## 怎么复用

- **知识复用**：引用旧反例、经验与诊断合同，不继承代码。
- **相同假设换条件**：原卡追加实验，明确新的框架与条件；原失败边界不覆盖。
- **核心机制/学习信号/假设改变**：新 Idea 引用旧卡，说明改变什么。
- **代码复用**：在实验的 reuse_scope 中记录源 commit 与路径；引用 Idea 不代表可继承失败代码。

复用前读原卡及直接证据，分清机制反例、实现缺陷、成本问题与特定条件下无收益。不能仅凭 supported/rejected 标签判断，也不根据更新时间自动采纳分支结论。

## 哪一份是当前结论

活跃或准备复用的 Idea 在 [Idea 树](IDEA_TREE.md) 指定一个 `current_record_ref`（保存卡片的准确 commit + 路径）和对应实验引用。不同分支结论未核对时写 `unreconciled`，不自动挑最新、最高分或 main 版本作为科学结论。

卡片实际更新并提交后，再更新这一个当前指针；其他 blob 版本都是历史或待对照内容。RECORD_INDEX.csv 只帮助找位置，不替代 current_record_ref。暂无活跃 Idea 时不创建空表、不猜测当前卡。

原有问题分类按需用于检索，不给每个类别创建新层级。所有历史卡无需一次性重写；被研究或复用时补齐必要边界。REUSE_INDEX 等旧导航仅供历史查找，不承担第二套结论。

## 更新与证据

开工明确假设；结束在原运行账本记事实，在卡片解释意义，在 main 首页只更新下一步。当前目录切回旧代码时，其旧卡与 README 不自动成为最新管理事实。

保留 method_originality 与 method_maturity 的区分；模块数量不等于创新数量。外部论文重新核对原文，来源存 papers/，PDF和缓存放仓库外并记录定位与必要身份；聊天和旧项目笔记不能代替论文证据。其余边界以 [AGENTS](../AGENTS.md) 为准。
